# Open Warehouse Tracker (OWT) v0.4.0

Open Warehouse Tracker extends Dolibarr's native warehouse workflows with barcode identification, internal locations, movable bins, picking, employee loans and operation history.

## Changes

- Rename the project, interface, module, service, configuration, permissions, storage objects, containers and packages to Open Warehouse Tracker / OWT. The Dolibarr module is `owt`, the service is `OwtApi`, and the module appears in the native Products family.
- Add a grantable operation-history permission, with a dedicated history page and history within item details. Searches, filters and pagination respect native product, warehouse and document access.
- Enforce independent module-access, create, modify, delete, move, consume, return, adjust, loan, picking, print, recovery and configuration permissions alongside Dolibarr's native permissions.
- Show pending synchronization intent in a More details table, including proposed item changes and stock movements.
- Add movable physical bins, item packing and recoverable whole-bin moves. Location and physical-bin labels resolve current contents and destinations.
- Save customer-order pick lists, track fulfillment and support audited manual completion with scanner safeguards.
- Support QR Code, Data Matrix, Code 128 and PDF417 through Dolibarr's barcode renderer. Thermal and A4 labels position compact 2D codes beside their details and wide 1D codes below them.
- Automatically expand generated identifiers from six to eight characters when all 28,629,151 six-character identifiers are occupied. Both lengths remain valid together, retain checksum protection and work across scanning, lookup, history and printing. Expansion persists across restarts and native synchronization.
- Add implementation documentation covering architecture, permissions, persistence, API contracts, barcodes and recovery.
- Stabilize browser tests and improve Code 128 decoding after video conversion and antialiasing.

## Replacement build, 16 November 2026

- Install locked frontend dependencies automatically before building, including build tools on production hosts. This prevents missing scanner dependencies after pulling updates; `--skip-install` reuses an existing installation.
- Use a warehouse icon for the module and its top menu, and replace the remaining QR Router heading on printed bin reports.
- Fix menu and native-tab permission expressions rejected by Dolibarr's restricted evaluator. Native grants remain required, and module endpoints continue to reject external/inactive users. Regression checks execute the official evaluators from Dolibarr 21 through 24.
- Select OWT when opening direct application links instead of inheriting Home or a stale menu ID. Explicit native menu contexts remain supported.
- Speed up validation by serving a prebuilt mock app, running browser engines in parallel CI jobs and running shared non-browser checks once. Branch pushes run all engines on Linux; pull requests and releases retain all nine browser/OS combinations.

After replacing the module files, disable/re-enable OWT to refresh its stored menus, tabs and icon, then sign out and back in. A leftover QR Router menu pointing to `/qrrouter/` belongs to the older module registration; remove that obsolete entry through Dolibarr's Menu editor as described in [troubleshooting](https://github.com/HatOnGithub/owt/blob/v0.4.0/docs/troubleshooting.md#old-qr-router-menu-remains-or-owt-is-greyed-out). This build does not migrate old module registrations or inventory.

## Installation

This release targets fresh OWT installations and uses the new names throughout. Install the `owt` module and matching service together, then configure the service URL and key in the module settings. The service entry point is `OwtApi.dll`; external configuration uses `OWT_CONFIG_FILE`. Container configuration uses `OWT_SERVICE_API_KEY` and `OWT_PORT`.

See the [installation guide](https://github.com/HatOnGithub/owt/blob/v0.4.0/docs/installation.md) and [project identity reference](https://github.com/HatOnGithub/owt/blob/v0.4.0/docs/code/project-identity.md).

## Downloads

- `module_owt-v0.4.0.zip`: installable Dolibarr module, including the production frontend.
- `owt-service-v0.4.0.zip`: matching portable business service; requires the .NET 10 ASP.NET Core Runtime.
- `SHA256SUMS`: SHA-256 checksums for both packages.

Dolibarr 21.0.2 or newer is required. Native API checks cover Dolibarr 21.0.2, 22.0.5, 23.0.4 and 24.0.2. The release workflow runs browser, decoder, service, gateway and native-API checks before publishing these assets.
